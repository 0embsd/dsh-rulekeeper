# 已知 flaky 用例登记

> flaky 的判据是「同一现场、同一输入、结果不稳定」。登记不是免死金牌：失败必须复跑并留输出；两次同向红按真缺陷处理，不走本通道。
> 维护：规则官；最后更新 2026-10-18。

## FLK-001 `test/gate-ci.test.mjs:332`

- **用例**：`判据: 恒报 CI_CARRIER_DONE=false；显式 --claim-remote 判红（本机模拟不冒充远端已执行）`（`test/gate-ci.test.mjs:323-337`）
- **不稳定断言**：`:332 assert.equal(ok.rc, RC.OK, ok.out)`
- **症状**：偶发 `ok.rc != RC.OK`；同用例其余断言（`:333` 恒报 false、`:335` claim 判红、`:336` finding 文本）未见单独失败。
- **复现与证据（2026-10-18）**：
  - 单文件连跑 6 次：`node bin/rk-test.mjs test/gate-ci.test.mjs`，6/6 `rc=0`、0 失败，**隔离态未复现**；
  - 全量一次：`node bin/rk-test.mjs`，`tests 967 / pass 966 / fail 0 / skipped 1`（197s），该用例未红；
  - 隔离态与全量态均未复现，故按「疑似 flaky」登记，**不按「已确认」处理**；待保留到失败现场后再升级。
- **可能触发面（待证，不作结论）**：full-suite 并发下 fixture 共享 / git 子进程时序。
- **处置约定**：
  1. 失败先原地复跑一次并保留两次完整输出；两次都红 ⇒ 按真缺陷处理，不走 flaky 通道；
  2. 只有「同输入、异结果」才继续留在此文件；
  3. 禁止用重试参数、放宽断言或删除用例来「修绿」。
- **负责人**：规则官（登记与复现）+ 插件维护（判据修正）。
- **下次检查**：full-suite 再次出现该用例红时，附失败输出、run 计数与环境，更新本节。
